# Единый тест Fast Start на Vast: порядок и критерии успеха

Один платный прогон измеряет весь путь и проверяет критерии. Скрипт: `tools/fast_start_test.py` (режим `simulate` — без денег и сети, проверяет сам тест; режим `live` — настоящий Vast). Заглушка API (`tools/stub_worker_api.py`) заменяет боевой backend: **боевая очередь, БД и `WORKER_SECRET` не затрагиваются** — у теста свой одноразовый секрет. Остановка через 60 с и учёт расходов — те же модули, что и в production (`FleetManager`, `accounting.usage`).

## Что делает тест
1. job 1 (`virality`) → CREATE инстанса → pull образа → контейнер → скачивание релиза по SHA → модели → CUDA → readiness → prewarm → claim → начало обработки.
2. job 1 завершён → через ≈ 60 с флот делает STOP (измеряется задержка от последнего задания).
3. job 2 (`beep`) → RESUME того же инстанса (измеряется быстрый путь; релиз и модели из кэша).
4. job 2 завершён → teardown: лог контейнера снимается **до** удаления, инстанс удаляется, проверяется, что не осталось ни одного `sonya-pool-*`.
Защиты: потолок `--max-usd` (по умолчанию и максимум 3) и `--max-minutes` (90) — при превышении тест прерывается и всё удаляется; teardown выполняется всегда (`finally`).

## Предусловия (все — действия владельца)
GitHub App создан и проверен `tools/verify_github_app.py` · базовый образ опубликован (digest) · `release/models.lock.json` заполнен (`docs/MODELS_FOR_MAC_MINI.md`) · релизный SHA закреплён · контрольное видео + эталонные результаты Mac mini · S3-ключ для теста (чтение `models/`, запись `fast-start-test/` и `fleet-metrics/`) · ключ Vast в файле `chmod 600` · на аккаунте Vast ≤ $5 · `cloudflared` (или другой туннель) на машине, где запускается тест.

## Запуск
```bash
# 0) симуляция (бесплатно): проверяет логику теста и оценщик критериев
python tools/fast_start_test.py simulate

# 1) туннель к заглушке API на время теста (отдельный терминал); URL вида https://xxxx.trycloudflare.com
cloudflared tunnel --url http://127.0.0.1:8787

# 2) preflight БЕЗ расходов: без --apply печатает проверки и ничего не запускает (exit 3 при любом FAIL)
python tools/fast_start_test.py live --release-sha <40hex> --image ghcr.io/…-base@sha256:<digest> \
    --backend-url https://xxxx.trycloudflare.com --control-video ~/controls/ctrl01.mp4 --max-usd 3

# 3) боевой запуск: нужны и --apply, и --confirm-spend, равный --max-usd
python tools/fast_start_test.py live … --max-usd 3 --apply --confirm-spend 3
```
Результат: `results/fast-start/report.md|json` (+ `worker-log.redacted.txt`). После прогона: закрыть туннель; `vastai show instances` должен быть пуст.

## Критерии успеха
**Автоматические (оценивает скрипт; любая красная — тест не пройден):**
| Критерий | Порог | Почему |
|---|---|---|
| Все задания завершены, 0 ошибок (`fail`, `WORKER_SHUTDOWN`, `mode_disabled`) | 2/2, 0 | отсутствие ошибок |
| CREATE: запрос → готов | ≤ 480 с (цель ≤ 240 с) | образ 3,75 ГБ по сети + модели ≈ 160 МБ |
| CREATE: ожидание пользователя (задание → начало обработки) | ≤ 600 с (цель ≤ 300 с) | первое видео после простоя > 30 мин |
| RESUME: запрос → готов | ≤ 120 с (цель ≤ 45 с) | образ не качается |
| RESUME: ожидание пользователя | ≤ 150 с (цель ≤ 60 с) | следующее видео после 60 с простоя |
| RESUME использовал кэш релиза/моделей | `release_cached=true`, модели ≈ 0 с | быстрый путь работает |
| Автоостановка после последнего задания | ≤ 90 с (правило 60 с + такты) | экономия GPU |
| Один инстанс: 1 create + 1 resume | точно | нет лишних запусков |
| Стоимость | ≤ **$3 (≈ 246 ₽)**; ожидаемо $0.2–0.8 (≈ 16–66 ₽) для RTX 3090/4090 при ≈ 1 ч | бюджет теста |
| Teardown | 0 оставшихся инстансов | нет утечек расходов |
| Логи и таймлайны без токенов/секретов | чисто | безопасность |
Пороги — предложение, основанное на расчётах (`FAST_START_REPORT.md`); после первого реального прогона их стоит пересмотреть по данным.

**Качество видео (после прогона; скрипт не может принять это за вас, поэтому в отчёте эти строки красные, пока вы их не заполните):**
1. *Технически:* для каждого клипа `ffprobe`: воспроизводится, длительность > 0, есть видео и звук, `virality` — 1080×1920, размер ≤ ≈ 45 МБ/мин (правило из CUT_PLAYBOOK, лимит Telegram).
2. *Сравнение с эталоном Mac mini:* `python tools/compare_runs.py --mode virality --input ctrl01.mp4 --baseline <git-ref> …` или `compare_runs.compare(эталон_dir, gpu_dir)` — число клипов, длительность (Δ ≤ 2 с), разрешение, звук, SSIM ≥ 0,90 там, где сравнимо, изменения `selected_segments.json`. Эталон для честного сравнения — прогон на Mac mini **с той же ASR** (faster-whisper той же модели, CPU): прежняя GigaAM даст другие границы фраз, это ожидаемо и не регрессия.
3. *Глазами (обязательно):* границы клипа на начале/конце предложения, субтитры верны и в такт, кроп держит говорящего без «отрезанных» лиц, нет чёрных кадров; для `beep` — все запрещённые слова закрыты (фикстура 5/5), ложных заглушек нет. Критерий: **не хуже эталона Mac mini**.
4. *Предупреждения режима:* в результате/логе нет `yolo11n.pt not found`, `webcam_detector.pt not found`, `… failed` — иначе модель не нашлась и качество тихо упало.
Заполнить: `quality.outputs_valid`, `quality.compare_verdict` в `report.json` (или повторно оценить `fast_start_test.evaluate`).

## Чего этот тест НЕ доказывает
Нагрузку (много заданий подряд), длинные видео, другие хосты (одно измерение ≠ распределение: повторить на 3–5 хостах), стоимость хранения в течение суток, качество `stories/educational/streamer/sonya_gen` (выключены).
