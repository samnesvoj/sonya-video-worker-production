# Релиз и откат

**Релиз = запись + явная команда владельца.** Merge в `main` ничего не выпускает.
1. PR смёрджен в `main`, CI зелёный на этом коммите (`test`, `secrets-scan`, `audit-deps`, `docker-build`).
2. Если менялись зависимости — обновить lock и опубликовать базовый образ (`publish-base-image`, вручную) → новый digest.
3. **GPU-проверка** нового SHA (docs/GPU_TEST_PLAN.md) — без неё в production не идём.
4. Actions → **release** → ввести `sha`, `version`, `confirm=RELEASE`. Workflow проверяет: SHA на `main`, manifest совпадает, четыре проверки зелёные именно на этом SHA, Trailer выключен; создаёт неизменяемый тег `worker-vX.Y.Z` и **черновик** GitHub Release с `release-record.json`. Образ не публикует, ничего не деплоит.
5. Деплой = **владелец** меняет `SONYA_RELEASE_SHA` (и digest образа при необходимости) в Vast Template / конфиге dispatcher. Только НОВЫЕ инстансы получают новый код; запущенные не меняются; остановленные с другим SHA уничтожаются, а не возобновляются.

## Откат
Вернуть прежний `SONYA_RELEASE_SHA` (+ digest). Релизы неизменяемы (SHA), старый код всегда доступен; плохие запущенные инстансы dispatcher останавливает/уничтожает (SIGTERM возвращает активные задания в очередь). Откат правки режима в Git — `git revert` через PR.
Список выпущенных SHA — теги `worker-v*` и записи Release; «последний хороший» SHA держите в заметке владельца рядом с Template.
